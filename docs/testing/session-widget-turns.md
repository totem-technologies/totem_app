## Results and remaining gaps

- All three changed files together: **39 passed** with
  `flutter test --no-pub test/features/sessions/screens/listening_turn_screen_test.dart test/features/sessions/screens/speaking_turn_screen_test.dart test/features/sessions/screens/receive_totem_screen_test.dart --reporter expanded`.
- Narrow `dart analyze` on those files: **no issues**. Modified files formatted.
- Unique coverage preserved: admission-filtered participant visibility; canonical
  order and late-next-speaker priority; no participant/control overlap; Keeper
  absence/status guidance; permission recovery; modified/focused/inactive key
  suppression; real pass/receive gestures and cues; prompt trimming and
  confirmation; receive failure/retry and duplicate-submit prevention; privacy
  guidance; small-screen/large-text control reachability; local participant
  identity; self-view preference, drag and persistence; explicit unmount cleanup.
- Live round-prompt replacement still needs a genuinely reactive provider fixture.
  Rebuilding ProviderScope override functions does not itself replace cached
  provider state; the historical no-prompt test did not protect that transition.
- Self-view settings coverage verifies projection and persistence after a provider
  preference command, not navigation to and interaction with the actual settings
  UI. That interaction belongs in its settings-screen coverage.
- Device/turn commands are external fakes here. Command commitment and rollback
  semantics remain covered in service/controller tests, not inferred from these
  widget command calls. No real device validation was performed.
